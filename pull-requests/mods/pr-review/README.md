# PR review

Native Herdr reviewer for GitHub PR files and unified diffs. Open it with the **Diff** button in the compact PR dashboard (**Review changes** in the full dashboard). It opens in a large centered modal covering 94% of the window width and 92% of its height, without creating tabs or changing your terminal layout. **Close** or Escape dismisses it; clicking the backdrop does not dismiss it. Unsubmitted inline comment drafts are lost on dismissal. Existing reviewer tabs and explicit tab/pane openings continue to work; the Close control only appears in a modal.

- **General comments:** The Comments tab loads PR-level discussion (GitHub issue comments) in GitHub-style cards: initial avatars, author headers, relative timestamps (exact time on hover), edited indicators, Author/association badges and links to the original GitHub comment. It loads when first opened; Refresh comments reloads it without discarding drafts. A separate composer provides Write / Preview tabs for local Markdown preview, a green Comment button (unavailable for empty/oversized drafts or while busy), and a two-step Discard draft / Confirm discard flow. Posting locks the composer; successful posting returns it to Write. Comment immediately publishes as the displayed account, after rechecking account identity. Markdown preview uses Herdr's local renderer, not GitHub's exact renderer; no preview request or write is sent to GitHub. This is separate from inline line comments, approval reviews and review summaries; those threads/summaries are not included. Closed/merged PRs can receive general comments if GitHub permissions allow. The first 1,000 discussion comments are loaded, with an explicit partial notice at the cap. Drafts are independent of inline drafts and survive tab switches/refreshes, but not closing or hot reload. Failed submissions preserve the draft; uncertain results warn to check GitHub before retrying, with no automatic retry.
- **Changed-file tree:** Files changed groups files into a collapsible directory tree, with folders first and names sorted within each folder. Folders start expanded; click a chevron or folder row to collapse/expand. Drag the divider between the file tree and diff to adjust the sidebar width (starts at 300px, adjustable from 180px to 900px while leaving room for the diff). The native split keeps its width across repaints and tab switches in the same reviewer. Leaves show filenames and change-status badges; hover for the full path (and original path for renames). Selecting a leaf opens its diff. Folder toggles preserve the selected diff and inline draft, and collapse choices survive tab switches and refreshes for the lifetime of the reviewer.
- **Code-first tabs:** a compact PR header and GitHub-style tab bar provide **Description**, **Files changed**, and **Checks**. **Files changed** is selected by default and gives the file list and diff the full remaining modal height. Only one tab's content renders at a time; there is no details drawer. Switching tabs preserves the selected file, snapshot and inline comment draft. The comment composer appears when returning to Files changed. Approval remains the green review action, while Merge is secondary; both keep their existing confirmations.
- **Description and labels:** the Description tab shows the PR author's rendered Markdown and rounded labels using their GitHub colors with contrasting text (hover for label descriptions). Empty descriptions and labels have explicit placeholders. The tab uses one scroll area filling the remaining modal height, with no nested vertical scrollers or expansion controls. It uses the existing PR snapshot with no extra requests; Refresh updates it without changing tabs.
- Changed files show status and addition/deletion counts; click one to view its patch.
- The diff has old/new line numbers, colored additions/deletions, horizontal scrolling and virtualized vertical scrolling.
- GitHub/Primer-style light and dark palettes follow Herdr's current appearance. Neutral code text on opaque green/red patch backgrounds, subtle blue-gray hunk headers, stronger line-number gutters and selected-file accents stay independent of terminal ANSI overrides. GitHub-style title/repo hierarchy, PR-state pills, branch chips, changed-file counters, compact icon rows, rounded file cards, and green primary actions bring the native panel closer to GitHub. Primary buttons and draft badges retain at least 4.5:1 text contrast. This styles the reviewer only, not the rest of Herdr.
- Renamed files show their previous path above the diff and in the file tooltip.
- Refresh fetches a new diff snapshot. Files and commits do not auto-refresh while you read.
- **Status checks:** the Checks tab shows a GitHub-style summary of passed, failed or running checks and all reported check rows automatically. The summary stays above a single full-height scrolling list with a draggable scrollbar. Rows show status icons, names, provider labels and descriptions; **Details** opens that check's HTTP(S) URL. Failing and pending checks appear first. Skipped, neutral, cancelled and unknown results remain distinct; no checks is not treated as passing. The Checks tab label includes a live status icon and loaded result count.
- Checks combine GitHub check runs (including Actions) and legacy commit statuses, pinned to the displayed head SHA. They refresh independently every 30 seconds, plus a dedicated ↻ button, without reloading files or disturbing an inline draft. New commits still require the main Refresh button. A checks API failure keeps the diff available and clearly marks retained checks stale instead of claiming success. Responses for an older snapshot are discarded.
- Each checks endpoint is paginated up to 1,000 entries; partial results carry a warning and cannot produce an all-passed summary. This reports checks on the displayed commit, not branch protection, required checks that have not reported yet, merge queue state, or merge eligibility. Access to private checks may require additional repository/SSO permissions; an endpoint error is shown rather than silently presenting a subset.
- The header identifies the head commit and branches. The PR head, base and file count are checked before/after fetching files; a detected concurrent change requires another Refresh.
- Missing patches (binary, empty or omitted) and patches whose addition/deletion counts do not match the API totals are labeled. This is a GitHub-provided patch preview, not a guarantee of full file context.
- To keep the UI responsive, previews are limited to 500,000 characters / 20,000 lines per file and 8,000,000 retained patch characters per pane. Files beyond those limits remain listed with a GitHub fallback notice.
- The files endpoint is paginated up to GitHub's 3,000-file cap; an incomplete list is explicitly labeled.
- **Merge…** is a secondary action in the Files changed toolbar, leaving code review as the primary task. It opens the shared `pr-merge` confirmation dialog for any open, non-draft PR (finish or discard an inline draft first), regardless of author, assignment, reviews or CI. It never merges immediately. The dialog shows the author, branches, reviewed head, account and a merge-method selector for merge commit or squash. Only repository-enabled methods can be selected; rebase is not supported. A prominent warning for PRs you did not author must be acknowledged before **Confirm merge** appears. Confirmation rechecks identity, permission, merge method and head/base revision, then sends a head-SHA-guarded mutation. GitHub enforces its checks, reviews, conflicts and repository rules. Cancel/Escape before confirming makes no change. No auto-merge, branch deletion or admin bypass. Confirmed merges update the modal's state badge and hide merge/approval actions; dashboard cards disappear through shared state. An uncertain submission warns to check GitHub, without automatic retry.
- **Open on GitHub** keeps the full browser experience available.
- **Inline comments:** click a diff line to open a multiline Markdown composer at the bottom of the review pane, below the diff. Deleted lines attach to the old (`LEFT`) side; added and unchanged lines attach to the new (`RIGHT`) side. Hunk headers and no-newline markers are not commentable. The composer shows the file, line, commit and account. **Add comment** explicitly posts immediately to GitHub without approving or merging. Draft and own PRs support comments too; GitHub enforces permissions.
- Inline comment drafts stay anchored when selecting another file, and nonempty drafts cannot be accidentally retargeted. Refresh is blocked until the draft is posted or explicitly discarded. Before posting, the panel rechecks identity, PR head/base/file count and open state, then sends the captured commit, path, line and side. A failed submission preserves the draft; an uncertain response warns to check GitHub before retrying. Drafts are in-memory only (closing/reloading the mod loses them).
- This version creates single-line inline comments only. It does not load existing threads, render posted comment bodies, reply/resolve threads, select code ranges, or batch comments into a pending review. A successful post shows a confirmation; use GitHub to view the thread.
- **Approve…** opens an inline confirmation showing the active GitHub account and reviewed commit. Confirming explicitly submits an APPROVE review pinned to that SHA, never a merge. It rechecks identity, head, base, file count and open/non-draft state; own PRs cannot be approved. GitHub enforces permissions. Refresh after new commits before approving. The panel prevents duplicate submissions for a commit it successfully approved during its lifetime, but does not load past reviews. A submission error can have an uncertain outcome; check GitHub before retrying.

## Permissions and limits

General discussion reads paginated `GET /repos/{owner}/{repo}/issues/{number}/comments`; Add comment sends `POST` to that same endpoint with a Markdown `body`, only on explicit click. It does not approve or merge. Uses `exec` to run the installed `gh` CLI: read-only `gh api` requests against the PR URL's host (including `/user` for account identity), plus `gh pr view --web` only on explicit browser clicks. Checks read `GET /repos/{owner}/{repo}/commits/{sha}/check-runs` and `GET /repos/{owner}/{repo}/commits/{sha}/status`; they never rerun/cancel jobs or change GitHub state. Explicit check Details clicks use the native `cx.open_url` with an HTTP(S) URL. Confirm approval sends `POST /repos/{owner}/{repo}/pulls/{number}/reviews` with `event=APPROVE` and the reviewed `commit_id`. This changes GitHub review state only after confirmation. **Add comment** sends `POST /repos/{owner}/{repo}/pulls/{number}/comments` with raw Markdown `body`, `commit_id`, current file `path`, typed numeric `line` and `side`. It publishes the comment immediately, only on an explicit Add comment click. Uses gh's active credentials; it does not read or store tokens. It performs no checkout, fetch, working-tree edit or merge. No local repository is required. Account changes in the dashboard also affect subsequent pane refreshes.
